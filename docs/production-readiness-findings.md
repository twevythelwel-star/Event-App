# EventBite production-readiness findings

**Reconciled:** 2026-11-01 against `main` at `c52e9c6` plus the current uncommitted working tree. This is a code/configuration review; no production environment was accessed. The earlier [production readiness audit](production-readiness-audit.md) is dated 2026-10-29 and is stale where noted below.

## Repository and architecture

- Recent committed history since the old audit: `9170c57` wired staff scanning and food handover to server operations; `83db6c1` randomized ticket tokens and locked redemption; `18432b1` added payment-state transition rules and locked refunds; `f9fd585` corrected organizer staff access; `16472b4` selected MySQL 8 and aligned the deployment guide; `ec2e275` added integer minor-unit money and configurable fees.
- Uncommitted payment work adds `Payment`, `PaymentWebhookEvent`, migration `000021`, `PaymentMethods`, processor configuration, admin approval endpoints, and host payment switches. It does **not** add provider SDK calls, payment-intent or capture endpoints, or a payment webhook route. `StripePaymentGateway` was still fabricating intent IDs, accepting caller amounts, and fabricating refunds; it is now disabled and throws on all transaction methods.
- The documented production entry point is Laravel Blade at `backend/public`; `src/` is a Vite React client that now renders connecting/unavailable/retry states until its API responds, with no bundled demo orders or events shown. The deployment guide says the SPA is not deployed.
- Database configuration supports SQLite and MySQL. The deployment guide selects MySQL 8; the committed CI workflow includes MySQL tests. App filesystem defaults to private local storage and requires persistent shared storage in production.

## Current payment method policy

As of this review, customer methods remain cash and organizer-configured manual bank/Zelle/Cash App transfer. Card, Apple Pay, Google Pay, Samsung Pay, Cash App Pay, and PayPal must remain unavailable until each has a working server integration and verified settlement path. Cash App transfer is a manual transfer method and remains distinct from Cash App Pay.

## Latest performance, accessibility, and verification pass

See [performance and accessibility verification](performance-accessibility-verification.md). Changes since the prior review include bounded event discovery, aggregated report queries, grouped target-market counts, bounded homepage sourcing, query fingerprint monitoring, additional indexes, and keyboard focus improvements. The full 278-test backend feature run is **not green** (2 errors, 39 failures), and no MySQL staging, provider sandbox, restore drill, load test, device camera scan, or screen-reader validation was available. ## Launch gate

Real card sales and card refunds are **not ready**. The safe code-side mitigation prevents card availability and provider-paid refunds from being recorded locally. A real provider integration, provider-backed refund flow, reconciliation, event-specific cancellation tests, operational alert verification and infrastructure drills still require implementation or an actual target environment.
