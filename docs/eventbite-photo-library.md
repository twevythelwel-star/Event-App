# EventBite photo library

The photo library holds photographs of **kinds of events** (a reggae concert, a Jamaican fish fry, a family picnic).
They illustrate events that have no flyer of their own. They are never presented as photos *of* that event.

**Status:** the library is built and tested. It holds **no photos yet**. Until photos are added and approved, every
event without a flyer keeps its generated artwork, exactly as before. No photo has been invented or generated by the
platform; each one must be supplied by a person with the rights to it.

## What a visitor sees

An event's cover picture is chosen in this order, everywhere (homepage, discovery, event page, tickets, the API):

1. **The host's own flyer**, uploaded or linked. Always first; a library photo never replaces it.
2. **An approved library photo of the event's kind**, labelled **"Illustrative photo"** on the image, with alt text
   saying it is not a photo of this event.
3. **The event's generated artwork**, labelled "Event artwork · no flyer uploaded yet" in the app.

Rules that keep pictures accurate:

* The kind comes only from the host's choice on the event form ("What kind of event is this?"). It is optional, and
  the title, description and category are **never** used to guess it. An event with no kind gets its artwork.
* A photo is shown only for its own kind. A picnic never gets a concert photo.
* Each event always gets the same photo, and events of one kind are spread across that kind's photos.
* A photo appears only after a second system administrator approves it, and disappears as soon as it is retired.

The homepage also shows **"Browse by kind of event"**: one card per group that has upcoming events, with an approved
photo when there is one (labelled), linking to `/events?kind=<group>`. The events list accepts `kind` as a group or a
single kind.

## Kinds of event (25)

| Group | Kinds |
|---|---|
| Music and entertainment | Reggae concert · Dancehall event · Live band · DJ set · Music festival · Outdoor concert · Nightlife event |
| Food and cultural events | Jamaican fish fry · Caribbean food festival · International food festival · Cultural celebration · Outdoor cookout · Street food market · Food vendor gathering |
| Community and family events | Family festival · Community gathering · Outdoor picnic · Cultural heritage event · Community fundraising event · Family entertainment day |
| Private and premium events | Wedding · Birthday celebration · Formal dinner · Private party · VIP entertainment experience · Corporate event |

Each kind has a written brief (subject, setting, people, lighting, framing) in `backend/config/photo_library.php`.
The admin Photo Library page shows each brief. Give the brief to a photographer, or use it as the prompt for an image
generator you are licensed to use commercially. Every brief asks for: no text, logos or brand names; no recognisable
real venue or landmark; natural people and hands; 3:2 landscape.

## Photography standards (checked at approval)

The reviewer must confirm all seven before a photo can go live:

1. Looks like a genuine professional photograph of this kind of event.
2. Realistic people: natural expressions, anatomy and proportions; no duplicated people, distorted hands or artificial faces.
3. Shows the actual kind of event it is filed under.
4. Believable lighting, venue, crowd and stage equipment for that kind of event.
5. No fake event logos, promotional text, brand names or watermarks.
6. Does not depict or suggest a real named venue or real named event.
7. The licence allows commercial use, and consent or a model release covers any identifiable people.

## How to add photos

1. Sign in as a system administrator, or an administrator with the *moderate content* permission, and open
   **Admin console → Photo Library** (`/admin/console/photo-library`).
2. Upload a JPEG, PNG or WebP of at least **1600 × 1000 px** (5 MB max). Fill in:
   * the kind, a title, and alt text (15–300 characters) describing what is in the photo;
   * the source (generated, licensed or commissioned), where it came from, the licence, and links if any;
   * whether identifiable people are shown, and whether a model release is on file;
   * the confirmation that you hold the rights.
   Click the preview to set the focal point (the part kept when the photo is cropped).
3. A **different** system administrator reviews it in the queue on the same page: they tick every standard and
   approve, or reject it with a reason.
4. To remove a photo, **Retire** it with a reason. It stops appearing at once. Its record and provenance are kept
   (soft deleted) for the audit trail.

Uploads, approvals, rejections, edits and retirements are written to the security audit log.

## How it is built

| Part | Where |
|---|---|
| Kinds, briefs, standards, minimum size | `backend/config/photo_library.php` |
| Table `library_photos`; column `events.photo_subject` | migration `2026_11_08_000066_create_photo_library.php` |
| Model (statuses, sources, model releases, `isUsable()`) | `app/Models/LibraryPhoto.php` |
| Choosing and storing photos | `app/Services/PhotoLibrary.php` |
| Cover order (flyer → library → artwork) and label | `app/Support/ResponsiveImage.php`, `<x-image-label>` |
| API (`coverImage.kind` = `flyer` / `library` / `artwork`) | `app/Http/Resources/EventResource.php`, `src/lib/imageResolver.ts`, `src/components/ImageLabel.tsx` |
| Admin page and actions | `app/Http/Controllers/Admin/PhotoLibraryController.php`, `resources/views/admin/photo-library/index.blade.php` |
| Validation | `StoreLibraryPhotoRequest`, `ReviewLibraryPhotoRequest` |
| Permissions | Gates `PHOTO_LIBRARY_MANAGE` and `PHOTO_LIBRARY_APPROVE` in `app/Support/AdminAuthorization.php` |
| Serving | `GET /api/v1/media/library/{id}` (public only when approved; managers can preview pending photos) |
| Tests | `backend/tests/Feature/PhotoLibraryTest.php` |

Storage: images are files on the media disk under `tenants/platform/library/…`. They are re-encoded on upload, and
small, medium and large WebP/AVIF copies are made. The database stores only paths and metadata, never image data.
